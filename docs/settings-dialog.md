# 托盘设置窗口

窗口沿用工具栏的蓝色强调色、圆角面板和深浅主题；支持主题即时预览、鼠标指针开关、恢复默认，以及 Tab / Enter / Space 操作。恢复默认只修改本窗口的四项设置，不重置标注属性。

快捷键支持 Ctrl、Alt、Shift、Win 与普通键组合。使用临时低级键盘钩子录入，只有点击快捷键区域后启用；等待组合键完全松开再移除，Esc 恢复原组合，失去焦点或关闭窗口会撤销录入并移除钩子。F12、占用或系统保留组合不能保存。未录入时无钩子、轮询或常驻绘制循环。

保存前检查快捷键占用，实际应用时再次注册；注册失败保持窗口打开并显示提示。取消不改变用户设置。保存继续使用现有配置文件，包含 Win 修饰键。

验证：build.bat（/W4 /WX）；settings_dialog、tool_preferences、cursor_capture、unified_toolbar、capture_to_pin、capture_reselect、capture_startup。设置专项覆盖 Win+Ctrl+F11、Esc、无修饰键、F12、失焦清理、冲突、恢复默认、取消、注册竞争。使用生产绘制代码生成 100% 浅色和 150% 深色预览并检查。真实 SendInput 用例仅在测试窗口能够取得前台焦点时执行；当前自动化环境无法取得该焦点，已明确跳过，尚不能视为真实 Win 键端到端验证通过。

实现预览：settings-dialog-light.png、settings-dialog-dark.png。

## 无边框亚克力修正

删除资源 CAPTION（该资源指令会隐式添加 WS_CAPTION），创建后显式移除标题栏与边框，并使用自定义非客户区。关闭对话框自动 DPI 布局，由同一个物理像素/DIP 布局流程处理真实窗口和控件尺寸，避免对话框二次缩放和底部裁切。

设置窗口使用一次性创建的系统 acrylic composition policy，背景模糊由系统合成器完成。完整窗口采用预乘 alpha 分层表面，圆角透明；原生按钮保留输入和焦点职责，视觉统一合成，避免不透明子窗口破坏材质。深浅主题更新材质；系统接口不可用时退回不透明面板。不抓桌面、不添加常驻刷新定时器。

新增验证真实 HWND 的样式、客户区/窗口范围相等、底部控件全部位于窗口内、透明圆角与背景 alpha，以及 UpdateLayeredWindow 成功。预览图使用生产完整窗口渲染叠加项目生成的彩色背景（100% 浅色、150% 深色），并非实际桌面模糊截图。自动化仍无法验证前台真实按键，系统最终桌面模糊观感也需交互环境检查。

安装后的 --background 启动不触发截图、已有实例不被激活，快捷键注册冲突时也不弹出设置窗口；仍可从托盘进入设置修改。没有增加开机启动项。

## 设置窗口的空闲内存隔离

设置现在由同一个 LumaShot.exe 的 --settings-worker 模式按需启动。它不读取用户配置、不注册托盘或截图快捷键、不加载 OCR。主进程仅通过继承白名单中的匿名共享内存和事件传递四项设置，保存回调仍在主线程执行，以保持快捷键注册与最终配置一致。取消或校验失败不提交设置；正常关闭后等待子进程退出。Job Object 保证主进程退出或安装更新时不会遗留设置子进程。

这使设置窗口初始化的图形、字体及输入法缓存随进程退出一并释放，避免它们常驻在托盘进程；没有使用工作集强制清理来压低显示值。

隔离测试（MiB，非用户当前进程）：旧的进程内设置约从 10.73 工作集 / 1.98 私有提交增长到 23.80 / 4.69。新的主进程连续三次打开关闭设置，从 11.20 工作集 / 2.47 私有提交 / 1.90 私有工作集变为 11.43 / 2.50 / 1.94。新版测量包含常驻 0.5 MiB 的工作集查询缓冲；不同环境不能只按绝对值比较。实际用户进程还可能加载输入法等附加模块，不保证每台机器的绝对内存数值相同。

idle_settings_memory 覆盖子进程取消、保存、父进程校验失败后重试、无关标注属性保留、子进程退出，以及主进程工作集/私有提交增幅限制。settings_dialog、capture_startup、tool_preferences 回归通过。
## 保留帧渲染（拖动不再卡顿）

用户反馈拖动设置窗口时卡顿。测量结果显示，窗口在屏幕内移动时不会重绘，但从屏幕外拖回、或经过其他窗口时，新露出的部分会触发 `WM_PAINT`。同时，每个露出的子按钮都会发送 `WM_DRAWITEM`，而 `WM_DRAWITEM` 原本会调用 `Refresh()`。结果是每移动一次鼠标就要完整软件渲染整个窗口好几次：40 次移动产生了 307 次全帧，耗时约 6 秒（150% 缩放，单帧 17–40 ms）。悬停、焦点变化和窗口激活同样每次都触发全帧。

现在的做法：

- `base` 保存不含控件的页面层。设置内容变化（`Refresh()`）时才渲染全帧：先把页面画进 `base`，再用像素对齐的位图复制把页面贴回，然后把各控件画到它上面。
- 悬停、焦点、按下、启用状态变化调用 `RefreshControl(id)`。重绘时 D2D 目标只绑定到这个控件的矩形，同样先贴回 `base` 的像素，再画控件。DC 渲染目标在 `EndDraw` 时会写回整个绑定区域，所以每一遍都必须完整恢复它绑定的那块像素。
- 纯露出时 `WM_PAINT` 只做验证（`BeginPaint`/`EndPaint`），不渲染也不上传。DirectComposition 会保留上一帧。
- `WM_DRAWITEM` 改为比对控件当前外观与上次绘制时的状态（焦点、禁用、按下、悬停），只有不同时才重绘这个控件。
- 激活窗口时，只有翻译引擎摘要真的变了才刷新。
- 工具面板拖动芯片时，只有插入位置变化才重绘，不再每次鼠标移动都画全帧。

局部帧与全帧的形状和颜色完全一致。LumaText 的字形边缘会随绝对浮点原点略有变化（实测最多 9/255，只出现在文字边缘），测试允许 16/255 以内的差异。

`lumashot_settings_test` 会输出 `Settings drag frames`、`Settings hover frame ms` 和 `Settings partial vs full`，并断言：拖动（包括从屏幕外拖回）不渲染全帧；露出不重绘；激活不重绘；悬停只做局部重绘；改动一项设置只渲染一次全帧。测试里光标没有被捕获，按钮滑到光标下时可能触发悬停，所以允许少量局部帧。

同一台机器上（4K，150%）的实测对比：

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 从屏幕外拖回 40 次移动 | 307 次全帧，约 6 s | 0 次全帧 |
| 悬停一个按钮 | 每次全帧约 21 ms | 局部帧中位数约 2–3 ms |
| 激活窗口 | 每次全帧约 25 ms | 0 帧 |
| 全帧（点击、换页） | 17–23 ms | 21–31 ms（多一个页面层） |
