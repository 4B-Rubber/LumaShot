# 自定义离线 OCR 模型

设置中的 OCR 模型目录可选择本地文件夹；恢复内置模型会清除该选择。目录必须包含非空的 `det.onnx`、`rec.onnx`、`dictionary.txt`。支持含空格和中文的路径。模型不会上传；加载、推理及完整兼容性验证在独立 OCR 工作进程中完成。

兼容范围是与内置 PP-OCR 预处理和 CTC 解码约定一致的 ONNX 模型，不是任意 OCR 引擎：

- 两个模型均只有一个 float32 输入和一个 float32 输出。
- 输入为 BGR、NCHW，通道数为 3、批次为 1 或动态；检测模型高宽均动态，识别模型高度为 48 或动态、宽度动态。
- 检测使用 ImageNet mean/std 归一化，输出 `[1,1,H,W]` 概率图；每个输出维度最多 4096。
- 识别使用 `(pixel/255 - 0.5) * 2` 归一化，输出 `[1,T,C]` CTC 分数，索引 0 为 blank。
- UTF-8 字典每行一个非空字符/词元，顺序与非 blank 输出类一致，允许 UTF-8 BOM 和 CRLF。若模型类别数为字典行数 + 2，会自动追加空格；若为行数 + 1，字典须已包含全部非 blank 类。动态类别维度按自动追加空格处理，并在推理时检查实际类别数。

设置页检查文件是否存在和非空，真正执行 OCR 时才检查模型格式与类别数。配置错误会显示识别错误，不会静默切换模型；可在设置中恢复内置模型后重试。切换只影响随后提交的识别任务，已经提交的任务继续使用提交时的配置。模型目录内容修改后请切换到内置模型执行一次识别，再重新选择自定义目录，以确保重新加载。

只加载可信来源的模型。LumaShot 不转换模型、不管理额外推理引擎，也不自动下载模型。

聚焦验证：从 `build` 目录运行 `lumashot_ocr_test.exe --models` 及 `lumashot_ocr_service_test.exe --custom-models`。后者使用内置模型的临时副本，验证中文/空格路径、损坏配置报错、字典不匹配和恢复内置模型；不读取个人文件或首选项。
